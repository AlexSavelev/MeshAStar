# MeshA*: более информативные эвристики и быстрое построение поля

Исследовательское расширение MeshA* в рамках студкемпа Яндекса и СПбГУ, октябрь 2026. Исследуем, когда учёт препятствий и ориентации сокращает время поиска траектории, и ускоряем подготовку эвристики с помощью очереди с корзинами.

Основа — реализация **MeshA*: Efficient Path Planning With Motion Primitives**, Marat Agranovskiy / PathPlanning. Исходный [README](README_UPSTREAM.md) и [MIT-лицензия](LICENSE.txt) сохранены. Этот репозиторий содержит наши изменения поверх полученной копии исходников; история исходного Git-репозитория в этой копии отсутствовала.

## Что реализовано

- **Safe Euclidean**: β·d_E, β=0,9933. Поправка учитывает несогласованность длины некоторых примитивов с расстоянием между их дискретными концами.
- **Max**: max(β·d_E, α·d_grid), α=0,9. d_grid — поле расстояний до цели с препятствиями на восьмисвязной сетке.
- **Directional**: усиление max направленными потенциалами и таблицами остаточной стоимости переходов между ориентациями. 16 проекционных направлений и 16 ориентаций робота — разные множества.
- **Buckets**: альтернативная очередь для построения того же grid-поля. Меняет подготовку эвристики, а не OPEN поискового алгоритма.
- Воспроизводимый стенд: фиксированные задачи, отдельные процессы, повторы, таймауты, проверка траекторий, остановка и продолжение прогона, анализ всех исходов.

Кинематическая таблица, additive и другие промежуточные эксперименты сохранены в коде, но не включены в основной набор сравнения. ML-эвристики и неподтверждённые реализации других участников в эту сборку не входят.

## Быстрый старт

Нужны **Python 3.9+, make, C++11-компилятор GCC или Clang**. Основной стенд использует только стандартную библиотеку Python. Поддерживаются macOS и Linux; на Windows — WSL. Ноутбуки и старые скрипты визуализации имеют дополнительные зависимости и для запуска стенда не нужны.

Все команды выполняются из корня репозитория:

```sh
python3 tools/prepare_final_benchmark.py --verify
make -f benchmark.mk -j2
make test -j2
python3 tests/benchmark_runner_tests.py
python3 tests/team_benchmark_tests.py
```

Короткая проверка восьми основных режимов на 64 краевых задачах (576 записей с эталонами):

```sh
python3 tools/run_benchmark.py --suite edge --matrix team8 --repeats 1 --out results/edge
python3 tools/analyze_team_series.py results/edge
```

Небольшой пилот на 24 задачах (216 записей с эталонами):

```sh
python3 tools/run_benchmark.py --suite pilot --matrix team8 --repeats 1 --out results/pilot
python3 tools/analyze_team_series.py results/pilot
```

Один повтор пилота проверяет работу стенда; его недостаточно для финальных выводов об ускорении.

## Полный эксперимент

960 задач на восьми картах, три повтора, восемь режимов: LBA* и MeshA* с safe-euclidean/max/directional плюс MeshA* с max-buckets/directional-buckets. Вместе с 960 эталонами LBA*/h=0 получается **24 000 записей**.

```sh
python3 tools/team_benchmark.py prepare
python3 tools/team_benchmark.py start
python3 tools/team_benchmark.py status
```

```sh
tail -f res/team-full-2026-10-29/run.log
python3 tools/team_benchmark.py stop
python3 tools/team_benchmark.py resume
python3 tools/team_benchmark.py analyze
```

`prepare` фиксирует исходники и входы в отдельном snapshot и собирает worker. `start` запускает фоновый процесс; сам по себе клон репозитория ничего не запускает. Старые результаты не входят в новый прогон. Не запускайте одновременно несколько измерительных серий на одном компьютере.

Ориентир на исходном ноутбуке — 8–10 часов; на другой машине время может существенно отличаться. ETA использует сохранённую историческую модель, а не гарантирует срок завершения. Опциональный профиль extended10 добавляет корзины для LBA*: 29 760 записей. Полные команды и правила resume — в [TEAM_FULL_TESTING.md](TEAM_FULL_TESTING.md).

## Как читать результаты

Главная метрика — `end_to_end_s`: подготовка, поисковый контекст, поиск, восстановление и очистка. `grid_s` уже входит в подготовку: складывать их повторно нельзя. Загрузка, прогрев и внешняя проверка записываются отдельно.

Ускорение считаем как отношение сумм медианных времён на одном наборе задач. Геометрическое среднее — отдельная метрика. Найденные пути, доказанная недостижимость и таймауты учитываются раздельно; timeout не означает отсутствия пути. `steps` — итерации внешнего цикла поиска, а не длина траектории. Стоимость одной итерации LBA* и MeshA* различается.

[Историческая сводка 27 октября](docs/results-2026-10-27/README.md) содержит проверенные агрегаты предыдущего эксперимента с шестью режимами. Это **не результат нового общего прогона с корзинами**. Новые результаты публикуются отдельно после завершения и проверки.
